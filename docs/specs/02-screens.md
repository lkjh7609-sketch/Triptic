# 02. 화면 명세

> 표기법: `[T]` 탭 루트 · `[S]` 스택(푸시) 화면 · `[M]` 모달/시트
> 각 화면은 §1의 공통 요구사항을 모두 만족해야 한다.

---

## 1. 공통 요구사항 (모든 화면)

1. 로딩 / 비어있음 / 오류 / 오프라인 4상태 구현 ([`01-design-system.md` §6.7](01-design-system.md))
2. 모든 문자열은 i18n 키 경유. **하드코딩 금지** (CI에서 검사)
3. 화면 진입 시 분석 이벤트 1건 (`screen_view`, 화면명만. 개인정보 금지)
4. 뒤로가기(스와이프 포함)로 항상 이전 화면에 도달. 안드로이드 하드웨어 백 키도 고려
5. 스크롤 위치는 탭 전환 시 보존

## 2. 홈 탭 — 대시보드 `[T]`

앱을 켰을 때 처음 보이는 화면. **"내가 얼마나 여행했는가"를 예쁘게 보여주는 것**이 목적이다.

### 2.1 구성 (위에서 아래로)

```
┌────────────────────────────────────┐
│  안녕하세요, 민수님 👋              │  인사 + 아바타
│                                    │
│  ┌──────────────────────────────┐  │
│  │ D-12    도쿄 여행             │  │  ⬅ 다음 여행 카드 (히어로)
│  │ 2026.05.20 – 05.23           │  │
│  │ ☀️ 도쿄 23°  ·  첫 일정 08:00 │  │
│  │ ✈️ KE801  인천 → 나리타       │  │
│  └──────────────────────────────┘  │
│                                    │
│  나의 여행 기록                     │
│  ┌────┬────┬────┐                  │
│  │ 12 │  7 │ 48 │  여행·국가·일수   │  ⬅ 통계 타일
│  ├────┼────┼────┤                  │
│  │ 23 │186 │1.2만│ 도시·장소·km     │
│  └────┴────┴────┘                  │
│                                    │
│  ┌──────────────────────────────┐  │
│  │      [세계지도 SVG]           │  │  ⬅ 방문 국가 채색
│  │   7개국 · 아시아 4 유럽 2 …   │  │
│  └──────────────────────────────┘  │
│                                    │
│  2026년                            │  ⬅ 연도별 타임라인
│  ●───●─────●──────────●            │
│                                    │
│  지난 여행                          │
│  [카드] [카드] [카드] →             │  ⬅ 가로 스크롤
└────────────────────────────────────┘
```

### 2.2 통계 정의 (정확히 이대로 계산할 것)

| 지표 | 정의 | 계산 |
|---|---|---|
| 총 여행 수 | 종료일이 오늘 이전인 여행 | `count(trips where end_date < today and deleted_at is null)` |
| 방문 국가 수 | 여행에 포함된 장소의 국가 코드 distinct | `itinerary_items.country_code` distinct |
| 방문 도시 수 | `trip_days.city_name` distinct | 같은 도시를 다르게 입력한 경우는 중복 집계된다 — 도시 정규화는 3.1 과제 |
| 총 여행 일수 | 각 여행의 `end_date - start_date + 1` 합 | 겹치는 날짜는 1일로 계산 (중복 제거) |
| 방문 장소 수 | `type in ('place','meal','activity')`인 항목 수 | 숙소·이동은 제외 |
| 총 이동 거리 | 확정된 `legs.distance_m` 합 | **항공 구간은 제외**하고 별도 표기 (수치가 왜곡됨) |

> 계산은 클라이언트가 아니라 Postgres RPC `get_user_travel_stats()`(인자 없음 — 내부에서 `auth.uid()` 사용, [`03-data-model.md` §5](03-data-model.md))에서 수행하고 결과를 5분 캐시한다. 클라이언트 집계는 여행이 많아지면 느려지고 오프라인 시 불일치한다.

### 2.3 상태별 동작

| 상황 | 화면 |
|---|---|
| 여행 0개 | 통계 대신 온보딩 카드 3장: "여행 만들기" / "예약 서류로 시작하기" / "샘플 여행 둘러보기" |
| 예정 여행 없음 (과거만) | 히어로 자리에 "다음 여행을 계획해 보세요" + 커뮤니티 인기 여행지 3곳 |
| 여행 중 (오늘이 기간 내) | 히어로가 **"오늘의 일정"**으로 바뀜: 다음 일정까지 남은 시간, 현재 위치 기준 이동 안내 |
| 비로그인 | 샘플 데이터로 통계 미리보기 + 흐림 처리 + "로그인하고 내 기록 보기" |

### 2.4 세계지도

- **Google Maps를 쓰지 않는다.** 지도 로드 SKU가 과금되고, 이 용도에는 과하다.
- 경량 SVG 월드맵(`src/shared/ui/WorldMap`)에 ISO 3166-1 alpha-2 코드로 `<path>` 채색.
- 방문국: `--brand`, 미방문: `--surface-sunken`. 탭하면 해당 국가 여행 목록.

## 3. 계획 탭 `[T]`

### 3.1 여행 목록 `[T]`

- 상단: "내 여행" + `+` 버튼
- 섹션: **예정** / **진행 중** / **지난 여행** (지난 여행은 접힘)
- 카드: 커버 이미지 · 여행명 · 기간 · D-day 배지 · 도시 칩 · 동행자 아바타
- 스와이프: 복제 / 삭제
- 비어있음: "첫 여행 만들기" + "예약 서류로 시작하기" (서류 업로드로 바로 진입)

### 3.2 여행 상세 `[S]` ⭐ 핵심 화면

레퍼런스 이미지의 구조를 따른다.

```
┌────────────────────────────────────┐
│ ←  도쿄 여행              🗺 🎟 ↗  │  ⬅ 뒤로 · 제목 · 지도/바우처/공유
│    2026.05.20 ~ 2026.05.23         │
├────────────────────────────────────┤
│ [+ 항공편] [가계부] [+ 서류]   ☀︎🌙 │  ⬅ 액션 칩 · 테마 토글
├────────────────────────────────────┤
│ (Day1) (Day2) (Day3) (Day4) →      │  ⬅ Day 칩
├────────────────────────────────────┤
│ Day1  5/20 (수)  ☀️ 16°/23°   편집 │  ⬅ 일자 헤더
├────────────────────────────────────┤
│ ✈  인천 08:00 – 나리타 11:00   ☀️  │  ⬅ 항공편 카드
│    대한항공 KE801 · 제2터미널   23° │
│    ├ 73.2km                        │  ⬅ 구간 라벨
│ ①  국제공항                        │
│    도쿄 나리타 국제공항             │
│    ├ 900m                          │
│ ②  13:00  4성급 호텔          ☀️  │
│    다이이치 호텔 도쿄          25° │
│    ├ 450m                          │
│ ③  일본라면 전문식당               │
│    라멘 타카하시                   │
│                                    │
│         [ + 일정 추가 ]             │
└────────────────────────────────────┘
```

**동작 규칙**

| 요소 | 동작 |
|---|---|
| 🗺 아이콘 | 지도 뷰로 전환 (§3.3) |
| 🎟 아이콘 | 바우처 보관함 (§3.6) — 미확인 바우처 수 배지 |
| ↗ 아이콘 | 공유 시트 (링크 생성/해제, 조회수, 제안 확인) |
| `+ 서류` | 서류 업로드 (§3.5) |
| Day 칩 | 해당 일자로 이동. 지도도 함께 갱신 |
| 편집 | 순서 변경·삭제 모드 진입 |
| 항목 탭 | 상세 시트 (주소·전화·영업시간·사진·길찾기·메모) |
| 항목 길게 누르기 | 드래그 순서 변경 |
| 구간 라벨 탭 | Google Maps 길찾기 딥링크 |

**데이터 로딩 순서** (체감 속도가 중요하다)
1. 캐시된 일정을 **즉시** 렌더 (IndexedDB)
2. 서버 일정 fetch → diff 반영
3. 날씨 fetch (병렬, 실패해도 일정은 정상 표시)
4. 경로(legs) fetch — 캐시 우선, 없는 구간만 Directions 호출
5. 각 단계는 독립적으로 실패 가능. **날씨나 경로 실패가 일정 표시를 막아선 안 된다**

### 3.3 지도 뷰 `[S]`

레퍼런스 이미지처럼 상단 지도 + 하단 바텀시트.

- **번호 핀**: 타임라인 번호와 1:1 일치. 활성 항목은 `--marker-fill-active`로 확대
- **경로**: 기존 `drawRoutesForViewMode` 로직 그대로. TRANSIT 실패 시 점선 폴백
- **존 분리**: 기존 `computeDayZones` 유지. 존이 2개 이상이면 지도 상단에 존 전환 칩 표시
- 바텀시트: Day 칩 + 해당 일자 타임라인 (스크롤 시 지도 핀 하이라이트 동기화)
- 현재 위치 버튼 (기존 `addCurrentLocationControl` 이식)
- **태블릿/웹**: 토글 대신 좌우 분할

> ⚠️ **이 화면이 Triptic의 차별점이다.** 리팩터링 중 경로 렌더링 동작이 바뀌면 안 된다. Phase 2 패리티 체크리스트로 검증한다.

### 3.4 일정 추가/편집 `[M]`

- 장소 검색 (Google Places Autocomplete, **세션 토큰 사용** — 비용 절감)
- 카테고리 자동 추론 (Places `types` → 관광/식당/카페/쇼핑/숙소/교통)
- 시간(선택), 메모, 예상 비용
- **근처 추천**: 기존 `openAiRecommendModal` 기능 이식 (Gemini→Groq→OpenRouter→큐레이션 폴백 유지)
- 좌표 없는 항목은 저장하지 않는다. 기존 앱은 `saveData()`/`renderList()`가 좌표 없는 항목을 **조용히 삭제**했는데(index.html:4505, 5504), 3.0에서는 입력 단계에서 막아 사용자가 잃는 일이 없게 한다. 좌표가 굳이 필요 없는 메모는 `type='note'`로 저장한다

### 3.5 서류 업로드 & 검수 `[M]`

→ 상세: [`04-document-ai.md`](04-document-ai.md)

```
1) 파일 선택 (PDF/이미지/.pkpass/.ics, 다중 선택 가능)
2) [동의 화면] "문서에서 예약 정보를 추출합니다. 여권번호·카드번호는
   전송 전에 자동으로 가려집니다."  [자세히] [동의하고 계속]
3) 진행 표시 (업로드 → 텍스트 추출 → 정보 인식 → 검증)
4) 검수 시트 — 인식된 예약 카드 목록
   ┌─────────────────────────────────┐
   │ ✈️ 항공편            신뢰도 높음 │
   │ KE801  ICN 08:00 → NRT 11:00    │
   │ 2026-05-20 · 제2터미널           │
   │ [Day 1에 추가]  [수정]  [무시]   │
   ├─────────────────────────────────┤
   │ 🏨 숙소          ⚠️ 확인 필요    │
   │ 다이이치 호텔 도쿄                │
   │ 체크인 [        ] ← 인식 실패    │
   │ [수정]  [무시]                   │
   └─────────────────────────────────┘
5) [일정에 추가] → 항목 생성 + 바우처 보관
```

**절대 규칙**: 사용자가 4단계를 거치지 않고 일정이 바뀌는 경로는 존재하지 않는다.

### 3.6 바우처 보관함 `[S]`

- 여행별 업로드 문서 목록. 타입 아이콘 + 예약번호 + 날짜
- 탭 → 전체화면 뷰어 (PDF는 pdf.js, 이미지는 확대/핀치)
- **오프라인 우선**: 여행 시작 3일 전 자동으로 전체 다운로드 캐시 (설정에서 끌 수 있음)
- 액션: 공유(시스템 시트) · Apple Wallet 추가(.pkpass) · 삭제
- 연결된 일정 항목으로 이동하는 링크

### 3.7 가계부 `[S]`

- 기존 경비 기능 확장: 카테고리·통화·결제수단
- **환율 자동 변환** (일별 환율 스냅샷 저장 — 나중에 환율이 바뀌어도 기록은 고정)
- 일자별/카테고리별 합계 차트
- (P1) 동행자 정산: 누가 얼마 냈고 누가 얼마 받아야 하는지

## 4. 커뮤니티 탭 `[T]`

→ 상세: [`06-community.md`](06-community.md)

### 4.1 피드 `[T]`

```
┌────────────────────────────────────┐
│ 커뮤니티                    🔍  🔔 │
├────────────────────────────────────┤
│ (도쿄) (오사카) (방콕) (파리) →    │  ⬅ 구독 중인 여행지
├────────────────────────────────────┤
│  전체  │  구독                      │  ⬅ 탭
├────────────────────────────────────┤
│ 🅤 민수 · 도쿄 · 6일 전       ⋮    │
│ 시부야 근처 숙소 추천해요...        │
│ [이미지] [이미지] [이미지]          │
│ ♡ 9   💬 8   ↗                     │
└────────────────────────────────────┘
```

- `⋮` 메뉴: 신고 / 사용자 차단 / 링크 복사 / (본인 글) 수정·삭제
- 차단한 사용자의 글·댓글은 피드에서 **완전히 제거**된다 (흐림 처리 아님)
- 무한 스크롤 (커서 기반 페이지네이션, `created_at + id`)

### 4.2 여행지 채널 `[S]`

- 헤더: 커버 이미지 · 여행지명(로케일) · 구독 버튼 · 글 수
- 정보 카드: 위치·통화·시차·최적 시즌·평균 기온 (기후 평년값 재활용)
- 글 목록 + "이 여행지로 여행 만들기" CTA

### 4.3 글쓰기 `[M]`

- 텍스트(최대 2,000자) + 이미지 최대 10장 + 여행지 태그(필수) + 내 일정 첨부(선택)
- **게시 전 자동 모더레이션** → 차단 시 사유 안내
- 이미지는 업로드 전 클라이언트에서 리사이즈(장변 1600px) + **EXIF GPS 제거**

### 4.4 글 상세 `[S]`

- 본문 + 이미지 캐러셀 + 좋아요 + 댓글(1단계 대댓글)
- 원문 언어가 사용자 로케일과 다르면 **"번역 보기"** 버튼
- 첨부된 일정 카드 → "내 여행으로 복사"

### 4.5 프로필 `[S]`

- 아바타·닉네임·소개·여행 통계(공개 범위 설정 가능)·작성 글
- 다른 사용자 프로필에는 **차단·신고** 버튼

## 5. 설정 탭 `[T]`

| 섹션 | 항목 |
|---|---|
| 계정 | 프로필 편집 · 연결된 로그인 · 로그아웃 · **계정 삭제** |
| 환경설정 | **언어**(한국어/English/简体中文) · 테마(시스템/라이트/다크) · 온도 단위(°C/°F) · 거리 단위(km/mi) · 기본 통화 |
| 알림 | 출발 전 리마인더 · 항공편 변경 · 커뮤니티 답글 · 마케팅(기본 꺼짐) |
| 데이터 | 오프라인 캐시 관리 · 내보내기(JSON/PDF) · 가져오기 |
| 정보 | 이용약관 · 개인정보처리방침 · 오픈소스 라이선스 · 문의하기 · 버전 |

```

  ↓
[경고 화면] 삭제되는 데이터 명시: 여행 N개, 바우처 N건, 커뮤니티 글 N개
  ↓
재인증 (소셜 로그인 재확인)
  ↓
"삭제" 입력 확인
  ↓
즉시: 로그아웃 + 모든 데이터 비공개 전환 + 30일 유예 예약
30일 후: auth.users 포함 완전 삭제 (Edge Function 스케줄러)
```

- 유예 기간 중 재로그인하면 복구 안내를 보여준다
- **웹사이트 링크로 대체 불가.** 앱 내에서 완결되어야 한다

### 5.2 언어 변경

- 즉시 반영 (앱 재시작 불필요)
- 변경 시 `profiles.locale` 저장 → 푸시 알림·서버 생성 콘텐츠에도 적용
- 서버 데이터(여행지 이름 등)는 새 로케일로 다시 fetch
