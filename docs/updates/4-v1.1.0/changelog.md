### 2026-10-09 (6) — 도트 캐릭터 랜덤 변경(설정) + 경비 0건 표시 + '결제방법'

- **도트 캐릭터를 설정에서 바꾸기**: 설정 > 내 정보 변경에 '도트 캐릭터' 칸 — 지금 모습 미리보기 + **랜덤으로 바꾸기**(누를 때마다 새 모습) + 바꾼 뒤에는 **처음 모습으로**(사용자 ID로 만든 원래 모습). 저장하면 통계 탭의 '나'와, 같이 다닌 친구 화면에도 내가 고른 모습으로 보인다. 저장 값은 `profiles.pixel_avatar_seed`(0105, **운영 DB 적용함**, 최대 40자, 본인 행만 수정)이고 공개 프로필 뷰 `community_profiles` 끝에 열로 덧붙였다(뷰의 기존 열·권한은 그대로). 동행자 조회(`useTripMembers`)가 이 값까지 가져온다.
- **경비 0건 표시**: 다녀온 여행에 경비 기록이 없어도 도넛(회색 고리)·결제방법(빈 막대)·여행별 비교 자리를 지우지 않고 항목을 전부 0원·0%로 보여 준다(하루 평균·여행당 평균·가장 비싼 여행도 ₩0). 안내는 한 줄('경비를 기록한 여행이 아직 없어요.').
- **'어떻게 결제했나' → '결제방법'**(en Payment method / ja 支払い方法 / zh-TW 付款方式).
- **확인**: 0건 경비 화면·설정 창(랜덤 → 처음 모습으로 버튼 등장)을 임시 화면으로 확인, 시험(시드 규칙·랜덤 값 40자 이하·서로 다른 모습·친구 시드) 추가. ⚠️ 실제 계정에서 저장·친구 화면 반영은 못 봤다.

### 2026-10-09 (5) — 통계 탭 문구·뱃지 다듬기

- **사용자 요청**: ① '여행에 함께 초대된 동행자만 보여요…' 안내 문구 삭제 ② 요약의 **'지구 둘레'** 타일 삭제(요약은 4칸) ③ 기록에서 **'아직이에요' 문구 삭제**(못 얻은 뱃지는 점선 회색 + 자물쇠만), **'지구 한 바퀴' 뱃지를 '여행 365일 달성'으로 교체**(누적 365일, `days365`) ④ **경비 안내 문구·'나의 여행 성향'을 한 줄로**(문구를 짧게 줄이고 넘치면 말줄임, 성향은 제목과 한 줄로 나란히).
- 이동 거리 줄('이동 N km')은 그대로 둔다. 4개 언어 문구 같이 수정, 시험은 365일 뱃지 기준으로 바꿈.

### 2026-10-09 (4) — 통계 탭: 같이 다닌 친구(전신 도트 캐릭터) + 모노라인 뱃지

- **사용자 요청**: 같이 다닌 친구들을 도트 아바타로(여행이 없거나 같이 다녀온 친구가 없으면 '나 혼자'), 뱃지는 이미지로. 첫 시안들은 못생기고 촌스럽다는 피드백 → **참고 이미지(큰 머리·작은 몸의 2등신 도트 커플)처럼** 아바타를 다시 그리고, **뱃지는 도트가 아니라 작은 모노라인**으로 바꿨다. 푸시 전에 사용자 승인을 받기로 했다.
- **같이 다닌 친구들**(요약 바로 아래): 내가 맨 앞('나', 초록 테두리), 이어서 다녀온 여행에 함께 초대된 사람들을 같이 간 횟수 순으로 — 이름·'N번 함께'. 친구가 없으면(여행이 0건일 때 포함) '나 혼자'와 안내 문구. 이름·동행자는 기존 `useTripMembers`를 그대로 써서 서버는 바꾸지 않았다.
- **도트 캐릭터**(`pixelArt.ts`·`PixelSprite.tsx`): 36×52칸 전신, 큰 머리에 작은 세로 눈·볼터치·입은 거의 없음, 짙은 윤곽선. 머리 6종(쓸어넘김·가르마 장발·올림머리·양 갈래·삐죽·단발)에 결 무늬·그림자, 옷 4종(정장+넥타이·원피스·후드·티), 안경/꽃핀 소품, 피부 5·머리색 9. 사용자 ID로 골라 사람마다 늘 같은 모습. 이미지 파일 없음.
- **뱃지**(`BadgeArt.tsx`): 44px 작은 동그라미 + lucide 선 아이콘(깃발·종이비행기·두 사람·지구), 숫자 뱃지는 숫자 + 작은 종류 아이콘(핀·가방·해). 얻은 건 브랜드 초록 선·연한 초록 바탕, 못 얻은 건 점선 회색 + 자물쇠. 한 줄에 촘촘히.
- **확인**: 아바타 24종·친구 줄·뱃지 12개를 임시 화면으로 확인, 시험(같은 seed=같은 모습·전신이 끊김 없이 이어짐·친구 계산). ⚠️ 실제 동행 여행의 친구 이름은 못 봤다.

### 2026-10-09 (3) — 통계 탭: 다녀온 여행이 없어도 0건으로 다 보여 줌

- **사용자 결정**: 지난 여행이 아직 없어도 '빈 화면'이 아니라 **모든 섹션을 0건으로** 보여 줘서 무슨 통계가 쌓이는지 알게 한다. 맨 위에 안내 띠('아직 다녀온 여행이 없어요' + 예정 N건 + 내 여행 보러 가기)만 붙는다. 세계 지도는 빈 지도, 경비·성향·연도별·여행별은 '생기면 쌓여요' 문구, 기록은 전부 '아직이에요'.

### 2026-10-09 (2) — 통계 탭(공항 오른쪽)

- **사용자 결정**: 공항 오른쪽에 '통계' 탭(PC 헤더·모바일 하단 6칸), **비로그인은 커뮤니티와 같이 로그인 창을 먼저 띄우고 접근 불가**(`guestAccess.requiresLogin('/stats')`, 시험 추가). 구성은 내가 구상한 안 그대로(아래 6장).
- **'다녀온 여행'** = 종료일이 오늘보다 앞선 여행(내가 소유했거나 멤버인 것). 예정·진행 중은 '예정 N건'으로만 센다.
- **화면**(`src/features/stats/`): ① 요약 띠(다녀온 여행·여행한 날·방문 도시·방문 나라·지구 몇 바퀴 + 이동 거리) ② 다녀온 곳(세계 지도에 나라 칠하고 도시 점 + 나라 칩 + 대륙별 비율 + '전 세계 195개국 중 N개국') ③ 경비(총액·하루 평균·여행당 평균·가장 비싼 여행, 카테고리 도넛, 결제수단 비율, 여행별 비교 막대) ④ 여행 습관(월별 횟수, 연도별, 평균·가장 긴 여행, 자주 간 도시, 많이 들른 곳, 맛집형/관광형/균형형 한 줄) ⑤ 여행별 통계(눌러서 펼치면 나라·이동 거리·항공사·장소 분류·일차별 지출) ⑥ 기록(첫 여행·첫 해외·3/5/10개국·5/10/20번째 여행·30/100일·지구 한 바퀴·첫 동행, 달성한 날짜 또는 '아직이에요').
- **서버**: `get_travel_stats()` RPC(0104, **운영 DB에 적용함**, 로그인한 사용자만 실행) — 여행마다 경비(기본 통화로 환산한 카테고리·결제수단·일차별)·장소 분류·항공 구간·일차 도시를 한 번에 집계. 여행 수만큼 상세를 부르지 않는다.
- **계산 규칙**: 나라·대륙은 여행 도시 좌표에서 가장 가까운 등록 도시(120km 안)로 정한다(여행에는 나라가 저장돼 있지 않다 — 못 찾은 곳은 '나라를 알 수 없어 빠졌어요'로 알림). 경비는 여행에 적어 둔 환율로 기본 통화까지 바꾼 값을 **현재 환율로 원화 환산**(환율 없는 통화의 여행은 합계에서 빼고 알림, 경비 기록 없는 여행은 평균에서 뺌). 이동 거리는 항공 구간이 있으면 그 합, 없고 해외면 인천 왕복 직선거리. 세계 지도는 구글 지도를 부르지 않는 정적 SVG(Natural Earth 110m 국경을 변환한 `worldMap.json` 113KB, 통계 화면에서만 불러옴).
- **확인**: 가짜 여행 10건으로 PC·모바일 화면 확인, 계산 시험 12개(나라·대륙·경비·환율 없는 통화·거리·성향·뱃지), 비로그인 로그인 창, 탭 위치. ⚠️ 실제 계정의 데이터로는 못 봤다(운영 DB에 지난 여행이 아직 0건) — 지난 여행이 생긴 뒤 숫자·지도가 맞는지 확인 필요.

### 2026-10-09 (1) — 도시 게시판 카드·동행 4열·게시판 줄 다듬기·스플래시 새 탭·PWA 도시 소개

- **도시별 게시판 사이드 카드**: '{도시} 여행 일정 만들기' 카드를 **'{도시} 날씨 및 시차'**로 — 설명 문구·'일정 만들기' 버튼 삭제(위쪽 헤더에 같은 버튼이 있다), 맨 위에 **도시 현재 시각(30초마다 갱신)** 과 그 아래 **'한국보다 N시간 느림/빠름'**(같으면 '시차 없음'). 추천 기간·최적 시기 줄은 그대로. 4개 언어 문구.
- **동행 게시판(동행 탭)**: PC는 **한 줄 카드 4개 × 2줄 = 한 쪽 8개** + 번호 쪽 넘김(`cardGrid`, `pageSize 8`). 모바일은 기존 세로 카드를 쪽당 8개로.
- **전체 탭 게시판 줄**: 분류 칸(`[자유게시판]`·`[도시]`)을 **고정 폭 열**로 줄마다 같은 자리에 맞춤(PC 108px·모바일 78px), 동행 알약은 오른쪽 **'동행 모집 · N명 남음'**(남은 자리 바로 앞), **줄 높이 일정**(PC 76px 이상) + 사진이 있는 글은 **제목 오른쪽에 56px 썸네일**(여러 장이면 +N). 사진 없는 글은 제목이 두 칸 폭을 쓴다.
- **스플래시가 PC에서 안 나오던 이유(재현함)**: ① 링크(`target=_blank`)·`window.open`으로 연 **새 탭은 먼저 열린 탭의 sessionStorage('이미 봤음')를 복사해 받는다** → 새 탭에서 안 나옴. 고침: 새로고침·앞뒤 이동이 아니고 연 탭(`opener`)이 있으면 새 탭으로 봄. ② **회선이 느리면**(3G 수준) 1.5초 안에 파일이 안 와서 조용히 건너뛰었고 '봤음'까지 남겼다. 고침: 준비 대기 2.5초, 파일 미리 받기(`preload`), **실제로 재생을 시작했을 때만 '봤음' 기록**. 남는 경우(설계): 같은 탭 새로고침, 탭 복제, 움직임 줄이기 설정, 아주 느린 회선.
- **PWA에서 '지금 가기 좋은 여행지' 도시 소개가 안 나오던 것**: 팝업의 도시 소개(AI)가 한 번 **'없음(null)'으로 받아지면 영구 보관(staleTime 무한) + 이 기기 캐시(IndexedDB 24시간)에 저장**돼, 오래 켜 두는 설치형 앱에서 소개 대신 기온·강수량 한 줄(대체 문구)만 계속 나왔다. 고침: 소개가 있을 때만 영구 보관, '없음'은 다시 열 때 다시 묻고, AI 쿼리의 null은 저장하지 않음(`shouldPersistQuery`, 시험 추가). ⚠️ 실제 PWA에서는 못 열어 봄 — 원인은 코드 추적으로 가장 유력한 것이며, 배포 후 PWA에서 확인 필요.

### 2026-10-08 (11) — 동행 표시를 알약 하나로 줄이고, 전체 탭은 게시판형(8개씩)

- **사용자 결정**: (10)의 동행 강조(초록 사진 칸·초록 테두리·왼쪽 띠)는 너무 튀어서 **되돌리고**, 칩 줄 맨 앞에 '동행 모집' 알약 하나만 둔다(색은 초록과 어울리는 호박색 `warning-tint`/`warning-text`, 다크 모드는 토큰이 따라간다). 도시별 게시판·동행 탭은 지금의 카드형 그대로.
- **전체 탭은 게시판형**: 긴 한 줄 목록 — PC는 머리줄(제목·작성자·작성일·좋아요·댓글)이 있는 표 모양, 모바일은 두 줄(제목 / 작성자·시간·숫자). 일반 글은 `[도시] 제목` + 사진 있으면 작은 사진 아이콘, 동행 모집글은 알약 + `[여행지] 제목` + 남은 자리(좋아요·댓글 칸 대신). **한 쪽 8개씩**(`PagedFeed`에 `pageSize`·`gridHeader` 추가, 기본 6은 그대로): PC 번호 쪽 넘김, 모바일 밀어넘기기+점. 구독 탭은 카드형 그대로. 게시판 줄에서는 좋아요 누르기·북마크가 없다(숫자만, 글을 열어서 누름). 새 파일 `BoardRow.tsx`·`BoardRow.module.css`, 문구 `feed.boardHead.*`(4개 언어).
- **확인**: 가짜 데이터로 임시 화면을 만들어 PC·모바일·밝은/어두운 테마를 헤드리스 크롬으로 확인(임시 파일은 지움). 실제 커뮤니티 화면은 로그인이 필요해 운영에서 확인 필요.

### 2026-10-08 (10) — 지도 구간 점선(경로 조회 제거) + 전체 피드의 동행글 '동행 모집' 표시

- **지도 점선(사용자 결정)**: 지도에서 지점끼리 구글 대중교통 경로(파란 선)를 자동으로 그리던 것을 없애고 **점선만** 긋는다. 이유는 호출량·비용 — 일정 하루의 구간마다 `DirectionsService`를 불렀고, 목록 화면(구간 라벨 거리)도 같은 호출을 따로 했다. 이제 `useTripRoutes`는 **구글에 아무것도 묻지 않는다**(구간 계산은 `useMemo`, 지도가 있을 때만 점선). 구간 라벨은 직선거리 `≈ 1.3km`로 바뀌었고(예전엔 경로 거리), 누르면 구글 지도 대중교통 길찾기 링크가 열려 거기서 경로를 본다(우리 API 호출 없음). `sharedDirectionsCache`는 PDF 내보내기가 쓰므로 남겼다(PDF 만들 때만 구간을 조회).

### 2026-10-07 (3) — 주변 추천: 쌓인 장소를 무작위로, 같은 정보를 쓰는 범위 500m

- **무작위**: 비슷한 자리에서 열면 늘 가장 가까운 같은 곳만 나와 재미가 없었다. 이제 쌓인 장소(풀) 중에서 묶음마다(식당·카페·볼거리) **무작위로 3곳**씩 고른다(`pickBalanced`, 서버·앱 같은 규칙). 기준 장소마다 따로 뽑히고, 앱이 이 기기에 저장해 두는 결과(react-query 캐시)라 같은 장소를 다시 열면 같은 목록이 보인다(바꾸려면 새로 뽑는 버튼이 필요 — 아직 없음).
- **범위 500m**: 쌓인 장소를 '같은 정보'로 보여 주는 범위를 1.5km → **500m**(서버 `POOL_RADIUS_M`, 앱 `NEARBY_POOL_RADIUS_M`). AI에게도 "500m 안(걸어서 5분)"으로 요청한다. 1.5km는 AI가 엉뚱한 곳을 지어낸 것을 거르는 안전선으로만 남겼다(그 안이면 풀에 쌓아 두어 다른 기준 장소에서 쓰인다).
- **한계**: 무작위는 쌓인 장소 안에서만 고르므로, 처음 AI가 만든 9곳뿐인 자리는 9곳이 늘 같다. 주변의 다른 기준 장소(겹치는 500m)에서 만든 것이 쌓일수록 후보가 늘어난다. 처음부터 후보를 더 만들려면 AI에게 묶음당 5~6곳씩 요청해야 하는데 응답이 느려진다(9곳 7초 → 15곳 약 11초 추정).
