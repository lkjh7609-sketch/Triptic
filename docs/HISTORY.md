# Triptic 개발 기록

이 파일이 프로젝트의 **유일한 진행 기록**입니다. 예전에 여러 곳에 흩어져 있던 진행 메모(`docs/triptic_3_0_rewrite_progress(필수 참고).md`, 루트의 `APP_OVERVIEW.md`·`USER_GUIDE.md`)와 커밋 기록, 작업 메모를 날짜별로 합쳤습니다. 원문은 [`archive/`](archive/)에 그대로 보관했습니다. `docs/MEMORY.md`는 AI 도우미 메모 목록의 오래된 사본이라 지웠습니다.

**기록하는 법**

- 새 작업은 [날짜별 기록](#날짜별-기록) 맨 위에 그날 날짜로 추가합니다(최신순).
- 한 날짜 안에서는 **바뀐 것 → 결정·교훈 → 남은 것** 순서로 적습니다.
- 앞으로도 계속 지켜야 하는 규칙이 생기면 [지켜야 할 원칙](#지켜야-할-원칙)에도 한 줄 추가합니다.
- API 키·비밀번호·개인 연락처는 적지 않습니다.

## 지켜야 할 원칙

### 개발·배포

- 커밋 전에 **다섯 가지 검사**를 모두 통과시킵니다: `npm run typecheck`, `npm test`, `npm run check:i18n`, `npx eslint src`, `npm run build`. 빌드 뒤에는 `git checkout -- public/sw.js`로 자동 생성된 캐시 이름 변경을 되돌립니다.
- 커밋은 기능·수정 단위로 잘게 나눕니다. 작업 중 발견한 버그 수정과 기능 추가는 따로 커밋합니다. 큰 단계가 끝날 때마다 이전 기능도 같이 회귀 확인합니다.
- 푸시는 **`origin`**(배포되는 저장소)에 합니다. `further`는 배포되지 않으므로 필요할 때만 올립니다. 푸시 뒤 CI와 Vercel 배포가 그 커밋으로 끝났는지 확인합니다.
- **기능이 사용자 데이터의 생애 주기(가입 → 삭제)에 닿으면 삭제까지 끝까지 확인합니다.** 탈퇴가 "요청 기록"에서 멈춘 채 방치돼 있던 적이 있습니다(2026-09-30). 안내 문구·방침이 약속한 동작을 실제로 해 보고 확인할 것.
- `api/` 바로 아래 `.js` 파일은 이름이 `_`로 시작하지 않으면 전부 Vercel 함수로 배포됩니다(개수 한도 있음, 테스트 파일도 포함). 테스트·공용 코드는 `api/_lib/`에 둡니다.
- `sw.js`는 **루트 파일**을 고칩니다(`public/`, `www/`는 빌드 산출물). `CACHE_NAME`은 `__BUILD_ID__` 자리표시자를 유지합니다. 빌드가 매번 바꿔 줘야 옛 캐시가 지워집니다.
- `privacy.html`·`terms.html`을 고치면 `node scripts/build.js`로 `public/` 사본을 맞춰 같이 커밋합니다.

### DB (Supabase)

- 운영 DB 스키마 변경은 적용 전에 사용자 확인을 받습니다. 먼저 `begin … raise exception`으로 결과만 보고 롤백하는 방식으로 검증합니다.
- 새 함수(RPC)는 Supabase가 자동으로 `anon`·`authenticated`에 실행 권한을 줍니다. 매번 권한을 다시 확인합니다.
- 권한 확인용이 아닌(non-SECURITY-DEFINER) 트리거 안에서 다른 사용자 행을 봐야 하면, SECURITY DEFINER 헬퍼 함수를 거칩니다. 호출자 RLS가 그대로 걸려 검사가 무력화된 적이 있습니다(0043).
- 요금제(`plan`)·권한(`role`)·핸들 같은 서버 관리 컬럼은 `guard_protected_columns` 트리거가 막습니다. 새 서버 관리 컬럼을 만들면 여기에 추가합니다.
- "버튼이 안 돼요" 신고는 클라이언트 코드보다 먼저 Supabase 로그에서 해당 RPC 호출이 서버에 닿았는지 확인합니다.

### 앱 코드

- `useQuery`의 결과는 JSON으로 저장 가능한 배열·객체만 돌려줍니다. `Map`·`Set`을 돌려주면 IndexedDB 캐시 복원 뒤 화면이 죽습니다(9/27 사고).
- 팝업은 바깥(어두운 배경)을 눌러도 닫히지 않습니다. 닫기·취소 버튼과 Esc로만 닫습니다. 새 팝업의 배경에 `onClick`을 달지 않습니다.
- 팝업 안에 팝업을 겹치면 바깥 클릭이 부모까지 닫는 문제가 반복됐습니다. 중첩할 때는 항상 이 부분을 확인합니다.
- iOS에서 새 탭을 여는 동작은 **클릭 즉시, `await` 없이** 해야 합니다. 미리 주소를 받아 두고 `<a href>`로 엽니다.
- `index.html`에 `canonical`·`og:url`을 넣지 않습니다. 모든 주소가 같은 파일을 받아서 전부 홈의 복사본으로 취급됩니다. 주소별 값은 로봇용 `api/seo.js`가 넣습니다.
- 한글 하드코딩은 `check:i18n`이 막습니다. 문자열은 번역 키로 넣고, 네 언어를 모두 채웁니다.

### 디자인 (모바일 UI 감사 이후 — 2026-09-30)

- **색은 역할별 토큰으로**: 채운 면(버튼·배지)은 `--brand-solid` + `--text-on-brand`(흰 글씨 5.47:1), 밝은 면 위 글자·링크는 `--brand-text`(4.5:1↑), 테두리·아이콘·포커스 링·밑줄은 `--brand`. `--brand`(#0D9488)를 글자나 흰 글씨 배경에 그대로 쓰지 않습니다(3.6~3.7:1). 상태색 글자는 `--success-text`·`--warning-text`·`--danger-text`. 흰색을 하드코딩하지 말고 `--text-on-brand`를 씁니다(다크 모드에서 하늘색 면 위 흰 글씨가 안 보이던 버그).
- **글자색**: 3단계는 `--text-primary`·`--text-muted`·`--text-tertiary`(4.5:1↑). `--text-placeholder`(2.5:1)는 입력창 placeholder 전용이라 글자로 쓰지 않습니다.
- **입력창·체크박스 테두리는 `--border-control`**(비텍스트 3:1). `--border`·`--border-strong`은 구분선·카드용입니다.
- **정의되지 않은 CSS 변수를 쓰지 않습니다**. 정의가 없으면 그 선언이 통째로 무효가 돼 배경·테두리가 사라집니다(`--surface-bg`가 AI 다음 장소 시트를 투명하게 만들었음). `tokens.css`에 별칭 11개를 두었습니다.
- **글자 크기는 rem(또는 토큰)** — px로 적지 않습니다. 일본어는 `html:lang(ja){font-size:87.5%}`로 전체가 두 단계 줄어드는데, px 글자는 여기서 빠지기 때문입니다. 최소 글자는 `--font-caption-size`(12px, 일본어 11.4px).
- **터치 기기 입력창은 16px 이상**(`global.css`의 `@media (pointer: coarse)` 규칙 하나). 확대 금지 메타(`user-scalable=no`)는 제거했습니다.
- **눌리는 영역 44px 이상**: 작은 컨트롤은 `::after`로 영역만 넓히고(보이는 크기 유지), `overflow:hidden`인 곳은 실제 높이를 키웁니다.
- **`:hover`는 `@media (hover: hover)` 안에**, 높이는 `100vh` 다음 줄에 `100dvh`. 그림자·모서리는 `--shadow-sm/md/lg`·`--radius-*` 토큰만 씁니다.
- **영어 UI**: 자동 하이픈은 문단(`p`·`li`)에만 켭니다(버튼·배지에서 `trav-/eler`로 잘림). 짧은 배지·상태 글은 `white-space: nowrap`, 그리드 칸은 `minmax(0, 1fr)`(안 그러면 nowrap 글 때문에 카드가 화면 밖으로 밀림).

### 보안 문서

- 보안 취약점 상세(어디가 약한지, 아직 안 고친 것)는 **git에 올리지 않고** `docs/private/`(`.gitignore`)에만 둡니다. 저장소가 공개될 수 있고, 약점 목록이 커밋에 있으면 푸시가 자동 안전 검사에서 막힙니다(2026-09-30 실제로 막힘).
- 이 기록·보고서에는 "무엇을 고쳤다"만 적고, 아직 안 고친 약점의 구체적인 이름·경로는 적지 않습니다.

### 제품 결정 (다시 제안하지 않을 것)

- 홈 히어로 검색 탭(여행 계획/항공/호텔/액티비티)은 만들었다가 사용자 요청으로 되돌렸습니다(6d4e768). **2026-10-01에 사용자가 시안(Stitch/Home)대로 다시 넣기로 해서 뒤집었습니다** — 지금 홈은 히어로 안의 항공·호텔·투어 캡슐(누르면 각 화면으로 이동)이고, 예전의 '검색창 있는 히어로 탭'과는 다릅니다. 홈에서는 헤더 아래 탭 줄(HomeSectionTabs)을 쓰지 않습니다(항공·호텔·액티비티 화면에는 그대로).
- **홈 특가 카드만** 시안 문구('실시간 수집'·'직항' 등)를 그대로 씁니다(사용자 결정, 2026-10-01). 마이리얼트립 값은 실시간이 아니고 직항 여부 정보가 없다는 사실은 그대로이고, `/flights`의 특가는 이전처럼 '실시간'이라 쓰지 않습니다.
- 항공 탭 제휴 위젯의 "Powered by 로고"는 사용자 요청으로 되돌렸습니다(e610c0e). 호텔 화면의 "Powered by Trip.com"은 유지합니다.
- 로고 재디자인 제안(Road T)은 사용자가 폐기했습니다.
- 트립닷컴은 자동화 브라우저를 인증 화면으로 막습니다. 우회하지 않고, 결과 화면 확인은 사용자에게 부탁합니다.
- LLM은 DeepSeek 공식 API를 먼저 쓰고 OpenRouter는 대체로만 씁니다.

### 2026-10-03 (5) — 여행 만들기 도시 입력: 구글은 그대로, 목록 모양만 "도시(나라)"

- **결정(사용자)**: 여행 만들기는 계속 Google을 쓰되 도시만 불러오고, 새 300곳은 **항공편 입력·커뮤니티**에 적용(이미 적용: 0079 적용, 공항 목록·여행지 300곳). 일차별 도시는 지금 그대로.

### 2026-10-02 (밤 3) — Sentry "View transition … document visibility state is hidden" 오류 정리

- **증상**: Sentry에 `InvalidStateError` 두 건(TRIPTIC-3 "Skipping view transition because document visibility state has become hidden.", TRIPTIC-4 "View transition was skipped because document visibility state is hidden."), 둘 다 iOS 18.7 Mobile Safari·각 1건. 화면 이동 애니메이션(`startViewTransition`)을 시작하려는데 앱이 백그라운드로 가 있어서 브라우저가 전환만 건너뛰며 던지는 오류 — **화면 이동 자체는 정상**(해롭지 않음).
- **조치**: ① `router.tsx`의 이동 감싸기에서 문서가 보이지 않을 때(`visibilityState !== 'visible'`)는 전환을 켜지 않음. ② 이동을 시작한 뒤 그 사이에 가려지는 경우는 막을 수 없어 `monitoring.ts`의 `IGNORED_ERRORS`(`/view transition.*visibility state/i`)로 Sentry 전송에서 제외(시험 포함). 다른 오류는 그대로 보낸다.
- **남은 것**: 배포 뒤 같은 이슈가 다시 안 쌓이는지 Sentry에서 확인하고, 두 이슈(TRIPTIC-3·4)는 Resolve 처리하면 됨.

**보고서 1차 개선 (측정 · 무료 한도 · 닉네임 · 모바일 첫 경험 · 활성화)**
- **닉네임**: 한글 2~7자 → 쓰는 글자별 글자 수. 한글 4~8자, 영어 4~12자, 일본어(가나가 있으면) 4~12자, 중국어(한자만) 2~6자. 한글이 있으면 한글, 아니면 가나, 아니면 한자, 그 밖은 영어 순으로 구분하고 이름 전체(공백·숫자 포함)를 셉니다. 예약어(관리자·admin·triptic 등)는 대소문자·구분 기호를 무시하고 막고, 중복 확인은 대소문자를 구분하지 않습니다. 서버 함수 `is_valid_display_name`(0062)과 화면(`src/shared/displayName.ts`)이 같은 규칙입니다. 이미 있는 이름은 바꿀 때만 검사해서 예전 3자 한글 이름은 그대로 쓸 수 있습니다. 마이그레이션 0060·0062, 운영 적용. `guard_protected_columns`에 `search_path`를 고정했습니다.
- **무료 한도 2개 → 5개(임시 완화)**: 한도를 사용자별 값(`profiles.trip_limit`, 기본 5)으로 저장합니다. 나중에 기본값을 바꿔도 이미 받은 사람의 한도는 그대로이고, 운영 콘솔 "사용자 등급" 칸에 "여행 n/5개 생성 · 한도 5개 적용(원래 2개)"이 보입니다. 사용자가 자기 한도를 못 바꾸게 보호합니다. 마이그레이션 0061, 운영 적용. `admin_search_users`의 비로그인 실행 권한도 회수했습니다.
- **측정**: 이벤트 10종(`signup_completed`, `trip_created`, `place_added`, `document_uploaded`, `share_link_created`, `share_joined`, `trip_limit_reached`, `onboarding_step_done`, `guest_trip_started`, `guest_trip_saved`)과 로그인 사용자 연결(무작위 UUID만). 클릭 자동 수집·화면 녹화는 끄고 쿠키 대신 localStorage, Do Not Track 존중. 개인정보처리방침에 PostHog·Sentry(국외 이전)를 추가했습니다. ⚠️ **운영에서 켜려면 Vercel에 `VITE_POSTHOG_KEY`·`VITE_POSTHOG_HOST`·`VITE_SENTRY_DSN`을 넣고 다시 배포해야 합니다**(`VITE_` 값은 빌드 때 들어갑니다). 키가 없으면 이벤트는 조용히 버려집니다.
- **모바일 첫 경험**: 모바일도 PC처럼 로그인 없이 둘러봅니다(첫 화면 로그인 벽 제거). 하단 탭의 마지막 칸은 비로그인일 때 "설정" 대신 "로그인"입니다. 로그인 전에도 여행을 만들 수 있습니다(임시 여행, 이 기기에 최대 2개). 일정은 고칠 수 있고 항공·서류·공유는 잠깁니다. 로그인하면 계정으로 옮기고 이 기기의 임시본을 지웁니다(`src/features/plan/guestTrips.ts`).
- **AI 생성 API는 로그인 사용자에게만**: `/api/recommend`·`/api/cityDesc`가 Supabase 토큰을 검증합니다(`api/_lib/auth.js`). 비로그인은 DB에 캐시된 추천·도시 소개만 보고, AI 추천 버튼을 누르면 로그인 창이 뜹니다. 보고서의 보안 1순위(비용 남용) 조치입니다.
- **운영 콘솔 "분석" 탭**: PostHog 이용 분석(방문자·가입·전환율·일별 방문자·많이 본 화면)과 Sentry 미해결 오류(많이 난 순)를 콘솔에서 봅니다. 서버 `api/adminAnalytics.js`가 관리자만 통과시키고 두 서비스에서 읽어 옵니다(1분 캐시, 키는 서버에만). 키를 안 넣은 쪽은 "연결 전"과 비어 있는 환경 변수 이름만 보입니다. 필요한 서버 환경 변수(`VITE_` 아님): `POSTHOG_PERSONAL_API_KEY`(개인 API 키, Query: Read 권한), `POSTHOG_PROJECT_ID`, `SENTRY_AUTH_TOKEN`(Project·Issue & Event·Organization 읽기), `SENTRY_ORG`, `SENTRY_PROJECT`. 브라우저용 공개 키(`VITE_POSTHOG_KEY` 등)와는 별개입니다.
- 분석 탭 수정: Sentry 요청에 넣던 기간 값(`statsPeriod=7d`)이 프로젝트 이슈 API에서 허용되지 않아(24h·14d만) 오류가 났습니다 → 기간은 검색어 `lastSeen:-Nd`로 바꿨습니다. 오류일 때 상대 서버의 HTTP 상태 번호(401 키·403 권한·404 이름·400 형식)만 화면에 보여 원인을 좁힐 수 있게 했습니다. 일별 방문자는 방문이 없던 날을 0으로 채우고 막대 폭에 상한을 뒀습니다(하루만 있으면 막대 하나가 화면을 채우던 것).
- **관리자 6자리 비밀번호(누르는 방식)**: 로그인하지 않은 방문자가 `/admin`을 열면 숫자 키패드가 뜨고, 맞으면 서버(`api/adminPin.js`)가 관리자 계정의 로그인 세션을 내려 줘서 그 기기가 관리자 로그인 상태가 됩니다(그래서 모든 관리 기능은 기존 관리자 권한 검사를 그대로 거칩니다). 시도 횟수 잠금은 DB(0063)가 전역·원자적으로 겁니다 — 어디서 누가 시도하든 합쳐서 5번 틀리면 15분 동안 잠기고, 잠긴 동안에는 비밀번호를 검사하지 않습니다. 비밀번호는 Vercel 서버 환경 변수 `ADMIN_PIN`(정확히 6자리 숫자, 뻔한 값은 서버가 거부) 하나이고 코드·저장소에는 없습니다. 계정 로그인은 그대로 남아 있어 잠겨도 들어갈 수 있습니다. 함수 개수 한도 때문에 `api/`의 테스트 파일은 `api/_lib/`로 옮기고 쓰지 않던 `api/env.js`는 삭제했습니다(`api/` 바로 아래 `.js`는 전부 공개 함수로 배포됩니다 — 테스트 파일도 배포돼 있었습니다).
- **운영 콘솔 여행 한도 조정**: 사용자 등급 탭에서 무료 사용자별 "여행 n/한도개 사용 · 남은 m개"를 보고, +1·+5·+10 버튼이나 직접 입력으로 한도를 정해 저장합니다(0~1000). 한도는 값 지정 방식(더하기 아님)이라 두 번 눌려도 이중으로 늘지 않고, 서버 함수 `admin_set_trip_limit`(0064, 관리자만)이 처리합니다. 생성 수는 여행을 지워도 줄지 않는 평생 누적입니다. 프로 사용자는 한도가 없어 생성 수만 보입니다.
- **회원 탈퇴 즉시 삭제(버그 수정)**: 예전 탈퇴는 `deletion_requested_at` 시각만 기록했고 "30일 뒤 삭제" 처리는 만들어지지 않아 계정이 영영 남았습니다(앱은 삭제된다고 안내하고 방침도 "지체 없이 파기"라고 했는데 실제로는 아님). 이제 `api/deleteAccount.js`가 방금(15분 안) 다시 로그인한 본인만 받아 ① 저장소 파일(예약 서류·게시 이미지·건의 스크린샷) → ② DB(`purge_user_data`, 0065; 나머지는 CASCADE) → ③ 로그인 계정 순서로 즉시 지웁니다. 도중에 멈춰도 다시 요청하면 이어서 끝납니다. 관리자 계정은 이 경로로 못 지웁니다. 앱 안내 문구와 방침도 실제에 맞췄습니다.
- **로그인 사용자별 AI 하루 한도**: `/api/recommend`·`/api/cityDesc`가 "LLM을 실제로 부르기 직전"에 최근 24시간 사용량을 확인합니다(캐시로 답하는 요청은 세지 않음). 무료 10회, 프로 100회(운영자는 프로와 같음), 두 API가 한 예산을 나눠 씁니다. 확인과 기록은 DB 함수 `take_daily_quota`(0066)가 원자적으로 해서 동시에 여러 번 눌러도 한도를 넘지 못합니다. 한도를 넘으면 429(`daily_limit`)이고, 앱은 "오늘 AI 추천 N회를 모두 썼어요" 안내(도시 소개는 조용히 비움)를 보입니다. 사용량을 못 확인하면 LLM을 부르지 않습니다. 숫자는 `api/_lib/aiQuota.js`의 `AI_DAILY_LIMIT`에서 바꿉니다.
- **정정(숫자)**: 보고서와 대화에서 "커뮤니티 글 3개·동행 모집 5개"라고 적었는데 삭제된 글(`deleted_at` 표시)과 취소·삭제된 모집까지 센 값이었습니다. 실제로 공개 중인 글과 모집은 0개입니다. 글·모집의 삭제는 행을 없애지 않는 숨김 처리라 그 행들은 DB에 남습니다. **개수를 셀 때는 삭제·취소된 것을 빼고 셉니다**(0067 이후에는 삭제된 글이 보관함으로 옮겨져 실제 테이블에는 살아 있는 글만 있습니다. 모집은 `status` 확인).
- **삭제한 글·모집을 보관함으로(0067)**: 예전 삭제는 행에 `deleted_at`(또는 상태)만 찍는 숨김이라 실제 테이블에 지운 글이 계속 섞여 있었습니다. 이제 사용자가 글을 삭제하면 그 순간 DB 트리거가 글을 `archived_content`(보관함)로 옮기고(댓글·이미지 정보 포함) 실제 테이블에서는 지웁니다 — 앱 코드는 그대로입니다. 동행 모집은 "성사된 적 없고 지원·채팅·정산·후기가 전혀 없는" 취소 건만 옮기고(그 밖에는 지우면 지원자·채팅·정산이 함께 사라져서), 운영자가 숨긴 것(`removed`)은 신고 기록이라 그대로 둡니다. 보관함은 이용자에게 공개되지 않고(RLS 정책 없음) 운영 콘솔 "보관함" 탭에서 읽기 전용으로 봅니다. 작성자가 탈퇴하면 보관함 항목도 함께 삭제되고, 다른 사람이 단 댓글은 그 사람이 탈퇴할 때 보관함에서도 지웁니다. 이미 숨겨져 있던 글 3개와 취소된 모집 3개는 한 번에 옮겼습니다. **개수를 셀 때는 이제 실제 테이블 = 살아 있는 것, 보관함 = 삭제된 것입니다.** 남은 일: 보관 기간(지금은 정해진 기간 없음)을 정하고 지우는 처리, 삭제된 글의 게시 이미지 파일이 공개 저장소에 그대로 있는 것을 비공개로 옮기기.
- **활성화**: 여행 상세에 "첫 여행 시작하기" 카드(장소 추가 · 예약 확인서 올리기 · 같이 갈 사람 초대, 진행 표시). 완료 여부는 실제 데이터(일정·서류·멤버·공유 링크)로 계산하고, 기기에는 "닫았다"만 저장합니다. 샘플 여행에는 안 보이고, 셋 다 하면 사라집니다.

**결정·교훈**
- 임시 여행은 소셜 로그인이 페이지 전체를 새로 여는 이동이라 메모리(샘플 방식)가 아니라 localStorage에 둡니다. 옮길 때 미리 정한 uuid로 저장해서, 도중에 실패해 다시 시도해도 같은 여행을 갱신할 뿐 중복으로 만들지 않습니다. 진행 중이면 한 번만 실행합니다(중복 생성은 곧 한도 낭비).
- 샘플 여행 id 특별 취급을 `isLocalTripId()`(샘플+임시)로 일반화했습니다. Supabase에 없는 여행은 서버 기능을 못 씁니다.
- Playwright는 `aria-disabled="true"` 버튼을 "비활성"으로 봐서 클릭이 막힙니다. 잠금 표시 버튼을 테스트할 때는 `force: true`를 씁니다.
- 마이그레이션 두 개가 같은 함수(`guard_protected_columns`)를 다시 쓰므로, 나중 것이 앞의 변경을 모두 포함해야 합니다(0061은 0060을, 0062는 0061을 포함).
